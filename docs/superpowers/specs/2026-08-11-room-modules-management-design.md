# TogetherSpace Room Modules Management Design

**วันที่:** 11 สิงหาคม 2026  
**สถานะ:** ผู้ใช้อนุมัติขอบเขตแล้ว  
**เป้าหมาย:** ทำให้อัลบั้ม บอร์ด การตั้งค่าห้อง สมาชิก และคำเชิญจัดการได้ครบ ใช้งานจริงได้ และมีรูปแบบแจ้งเตือนที่สม่ำเสมอ

## ขอบเขตที่ยืนยันแล้ว

- ทำระบบจัดการอัลบั้ม บอร์ด ห้อง สมาชิก และคำเชิญให้ครบตามสิทธิ์
- ตรวจการทำงานจริง เติม loading, empty, success และ error state ที่ยังขาด
- ยังไม่เชื่อมอัลบั้มกับปฏิทิน
- ประเภทห้องกำหนดตอนสร้างและไม่สามารถเปลี่ยนภายหลัง
- การเก็บรายการบนบอร์ดใช้ `archived_at` เพื่อซ่อนจากบอร์ดหลัก
- ยังไม่ทำหน้ารายการที่เก็บไว้ การกู้คืน หรือลบรายการบอร์ดถาวร
- ไม่เปลี่ยน schema, migration, RPC หรือ RLS ในงานนี้
- ไม่เพิ่ม dependency สำหรับระบบแจ้งเตือน

## 1. ระบบแจ้งเตือนกลาง

สร้าง Dialog และ Toast ที่ใช้ร่วมกันทั่วแอป โดยยึดธีม Living Room After Dark

- Dialog ไม่มีไอคอน
- หัวข้อขนาดใหญ่ จัดกึ่งกลาง
- รายละเอียดจำกัดความกว้างและจัดให้อ่านสวยภายในหนึ่งถึงสองบรรทัด
- ปุ่มยกเลิกและปุ่มยืนยันมีลำดับชัดเจน
- รองรับ Escape, คลิกฉากหลัง, focus lock และคืน focus หลังปิด
- ปิดการกดซ้ำระหว่างคำสั่งกำลังทำงาน
- Toast แสดงสำเร็จหรือผิดพลาดชั่วคราวและไม่บังคับเปลี่ยนหน้า

นำไปใช้กับการเก็บรายการบอร์ด ลบรูป ยกเลิกคำเชิญ นำสมาชิกออก ออกจากห้อง และลบกิจกรรมปฏิทิน

## 2. อัลบั้ม

- อัปโหลดหลายรูปพร้อม validation ชนิดและขนาดไฟล์
- แสดงความคืบหน้าและผลลัพธ์การอัปโหลด
- เปิดภาพใน modal และเลื่อนภาพก่อนหน้า/ถัดไป
- แก้วันที่และคำบรรยายของภาพ
- ลบข้อมูลรูปและไฟล์ใน Supabase Storage
- เจ้าของรูปจัดการรูปตัวเองได้ และเจ้าของห้องจัดการได้ทุกภาพ
- ลากจัดลำดับภาพภายในวันเดียวกัน พร้อมคืนลำดับเดิมเมื่อบันทึกล้มเหลว
- ถ้าไม่เลือกวันที่ ใช้วันที่อัปโหลด
- เพิ่ม empty, loading และ error state รวมถึง responsive layout

## 3. บอร์ด

- เพิ่มและแก้ไข Note
- เพิ่มและแก้ไขหัวข้อ รายละเอียด และรายการย่อยของ Checklist
- ติ๊กและยกเลิก Checklist ได้
- เพิ่มและแก้ไข Poll กับตัวเลือก
- Poll รองรับโหวตข้อเดียวหรือหลายข้อ และยกเลิกคะแนนเดิมได้เสมอ
- แสดงจำนวนคะแนนและตัวเลือกของผู้ใช้ให้ชัด
- เก็บรายการด้วย Dialog ใหม่ แล้วแสดง Toast เมื่อสำเร็จ
- ปรับรูปแบบ Card ให้แยก Note, Checklist และ Poll ได้ง่าย
- เพิ่ม empty, loading และ error state

## 4. ห้อง สมาชิก และคำเชิญ

### เจ้าของห้อง

- แก้ชื่อห้องและรูปห้อง
- ลบรูปห้องเก่าจาก Storage หลังบันทึกรูปใหม่สำเร็จ
- ไม่มีช่องเปลี่ยนประเภทห้อง
- สร้าง คัดลอก และยกเลิกคำเชิญ
- แสดงสถานะคำเชิญที่ใช้งานได้ หมดอายุ ครบจำนวน หรือยกเลิกแล้ว
- เปลี่ยนบทบาทสมาชิกและนำสมาชิกออก

### สมาชิกทั่วไป

- แก้ชื่อและรูปโปรไฟล์เฉพาะห้อง
- ดูรหัสห้องและข้อมูลสมาชิก
- ออกจากห้อง
- ไม่เห็นคำสั่งที่ไม่มีสิทธิ์

## 5. หน้าหลักและคุณภาพ UX

- ตรวจ responsive ของส่วนหัว เมนู การ์ดโมดูล และรายชื่อสมาชิก
- รักษาข้อความเฉพาะประเภทเพื่อน คู่รัก และครอบครัว โดยประเภทห้องไม่เปลี่ยนภายหลัง
- ทำสถานะว่าง โหลด สำเร็จ และผิดพลาดให้เป็นรูปแบบเดียวกัน
- ลดการดึงข้อมูลและ render ซ้ำเท่าที่ทำได้โดยไม่เปลี่ยนพฤติกรรมระบบ
- แยก component และ CSS ตามหน้าที่เพื่อให้อ่านและนำกลับมาใช้ซ้ำง่าย

## 6. สิทธิ์และข้อมูล

- UI ซ่อนคำสั่งตามบทบาท แต่ Server Action และ RLS ยังคงเป็นชั้นตรวจสิทธิ์จริง
- ใช้โครงสร้างฐานข้อมูลปัจจุบันเท่านั้น
- ถ้า RLS ปัจจุบันขวางพฤติกรรมที่กำหนด จะหยุดเฉพาะส่วนนั้นและรายงานสิ่งที่ Backend ต้องแก้
- การลบรูปต้องลบแถวฐานข้อมูลและไฟล์ Storage โดยไม่ลบไฟล์ผิดรายการ

## 7. การตรวจสอบ

- ทดสอบ flow เจ้าของห้องและสมาชิกทั่วไป
- ทดสอบเพิ่ม แก้ ลบ และลากเรียงรูป รวมถึง Storage cleanup
- ทดสอบเพิ่ม แก้ โหวต ยกเลิกโหวต ติ๊ก Checklist และเก็บรายการบอร์ด
- ทดสอบสร้าง คัดลอก ยกเลิกคำเชิญ เปลี่ยนบทบาท นำสมาชิกออก และออกจากห้อง
- ตรวจ keyboard/focus ของ Dialog และ Modal
- ตรวจมือถือ แท็บเล็ต และเดสก์ท็อป
- รัน unit tests, typecheck, lint และ production build
- อัปเดต README และเอกสารสถานะ Phase 2 ให้ตรงกับสิ่งที่ทำจริง
