# UI Feedback, Crop, Album, Board และ Responsive Design

## เป้าหมาย

ทำให้หน้าครอป อัลบั้ม และบอร์ดใช้ง่ายขึ้น พร้อมสร้างรูปแบบกลางสำหรับข้อความตอบกลับ การตัดบรรทัด ไอคอน Modal และธีม เพื่อให้ทุกหน้ามีพฤติกรรมสม่ำเสมอทั้งมือถือ แท็บเล็ต และเดสก์ท็อป

## ขอบเขต

### 1. Modal และ Crop

- Modal ทุกตัวเว้นระยะจากขอบ viewport และไม่ล้ำถึง Header
- เนื้อหาที่ยาวเลื่อนภายใน Modal โดย Header และปุ่มคำสั่งยังเข้าถึงได้
- หน้าครอปแสดงภาพในกรอบที่พอดีกับ viewport มีคำอธิบายการใช้งาน และจัด control ซูม/ตำแหน่งให้อ่านง่าย
- ปุ่มใช้รูปและยกเลิกมีไอคอนที่สื่อความหมาย

### 2. Album

- ก่อนอัปโหลดหลายรูปต้องมี preview grid พร้อมชื่อไฟล์และปุ่มเอาออกจากคิว
- Modal ดู/แก้ไขรูปจัดภาพและฟอร์มเป็นสัดส่วน จัดวันที่และคำบรรยายให้ตรงแนว
- ปุ่มลบใช้ไอคอนถังขยะและถามยืนยันตามเดิม
- Modal ไม่ชน Header และรองรับภาพแนวตั้ง/แนวนอน

### 3. Board

- หน้าหลักลดความหนาแน่นของ controls และคงการ์ดรายการให้อ่านง่าย
- การกดแก้ไข Note, Checklist และ Poll เปิด Modal แทนการขยายฟอร์มในรายการ
- การแก้ไข checklist/poll ภายใน modal ต้องคงการเพิ่ม ลบ เช็ค และโหวตเดิม
- Modal ไม่ปิดเมื่อคลิกพื้นหลัง และปิดด้วยปุ่มปิดหรือยกเลิกเท่านั้นตามพฤติกรรมเดิมของโปรเจกต์

### 4. ระบบกลาง

- Toast สำเร็จ/ผิดพลาดแสดงชั่วคราว 2.5 วินาทีแล้วหาย โดยผู้ใช้ปิดเองได้
- ฟอร์มบันทึกหลักเปลี่ยนข้อความสำเร็จแบบค้างเป็น Toast
- ข้อความหลังอัปโหลดรูปเป็นสองบรรทัด: “อัปโหลดรูปแล้ว” และ “กรุณากดบันทึกเพื่อใช้รูปนี้”
- ปรับไม้ยมกให้ติดคำก่อนหน้า เช่น “อื่นๆ” และ “เล็กๆ” ในข้อความ UI
- การ์ดทางลัดใช้ข้อความ 1 บรรทัดเมื่อสั้น และไม่เกิน 2 บรรทัดเมื่อยาว โดยความสูงไม่เปลี่ยนตามข้อความ
- ไอคอนใช้กับ action ที่ต้องสแกนเร็ว ได้แก่ เพิ่ม อัปโหลด แก้ไข ลบ ปิด ย้อนกลับ คัดลอก และบันทึก แต่ไม่เพิ่มในปุ่มที่ข้อความชัดและพื้นที่จำกัด

### 5. Theme

แต่ละประเภทห้องมี 4 ธีมและเลือกข้ามประเภทไม่ได้:

1. TogetherSpace
2. Warm Light
3. ธีมเฉพาะประเภทแบบมืด
4. ธีมเฉพาะประเภทแบบสว่าง

- Friend: Midnight Crew และ Day Trip
- Couple: Rose Evening และ Blush Morning
- Family: Calm Home และ Sunny Home โดย Sunny Home ต้องสดใส อ่านง่าย และเป็นมิตรกับทุกวัย

ธีมเปลี่ยนทั้งหน้าเว็บและจำค่าเฉพาะห้องในเบราว์เซอร์เครื่องนั้น

## Responsive

- Mobile: Modal กว้างเต็มพื้นที่ที่เหลือ, controls เรียงแนวตั้ง, preview 2 คอลัมน์เมื่อพอและ 1 คอลัมน์บนจอแคบ
- Tablet: ฟอร์ม/ภาพแบ่งพื้นที่สมดุลและไม่มี horizontal overflow
- Desktop: ใช้ความกว้างสูงสุดที่อ่านง่าย ไม่ยืดข้อความหรือช่องกรอกเกินความจำเป็น

## การตรวจสอบ

- Unit test: theme catalog, copy normalization, toast timeout helper และ board edit-state
- Typecheck, ESLint และ production build
- Browser visual check ที่ desktop และ mobile เมื่อมี session เข้าสู่ระบบพร้อมใช้งาน

## งานที่ไม่รวม

- ไม่เปลี่ยน schema หรือ RLS
- ไม่เพิ่มประเภท Board เฉพาะ Friend/Couple/Family ในรอบนี้
- ไม่เพิ่ม dependency ใหม่
